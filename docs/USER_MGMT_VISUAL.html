Design vs Architecture Mismatch — Muaath Needs to Update

Nigel's architecture (phone-first) and Muaath's current mockup (invite-first) diverge on 3 points:

  • 1. Flow order: Muaath's mockup shows Welcome → Invite Code → Bulk Capture. Nigel specifies Welcome → Phone Input → OTP → Invite Code → Profile Setup. The invite code moves AFTER authentication.
  • 2. Missing screens: Muaath has no phone input screen, no OTP verification screen, and no SMS/WhatsApp channel toggle. These are new screens in Nigel's architecture.
  • 3. Phone input UX: Nigel specifies a UAE phone input with +971 prefix, SMS/WhatsApp segmented control, and "Use email instead" link. Muaath's mockup starts with invite code entry directly.

Action: Muaath needs to redesign the onboarding section (frames 1a-1b) to match Nigel's phone-first flow. The bulk capture screen stays but moves to after profile setup, not right after invite code.

Key Facts

Auth Tiers

  • Primary: UAE SMS OTP (Twilio, $0.015/msg)
  • Secondary: WhatsApp OTP (Twilio WA, $0.021/msg)
  • Tertiary: Email/password (existing, kept as fallback)
  • Local dev: test_otp map — zero cost, no SMS
  • Account linking: Phone + email on same user

New Screens Needed

  • phone-input.tsx — phone entry + SMS/WA toggle
  • phone-otp.tsx — refactor to real OTP entry
  • email-login.tsx — email/password fallback
  • src/lib/phone.ts — UAE normalization utility
  • send-otp/ — edge function for WhatsApp routing

Database Changes

  • Migration 0008: phone NOT NULL UNIQUE
  • New table: otp_attempts (rate limiting)
  • New columns: email, preferred_otp_channel
  • Triggers: sync_profile_phone, handle_new_user
  • RLS: circles SELECT for authenticated invite validation

Cost (5-15 users)

  • SMS: ~$0.45/month (30 msgs)
  • WhatsApp: ~$0.62/month (30 msgs)
  • Sender ID registration: One-time ~$0-25
  • Total: ~$1-3/month — well within $20-50 budget
  • Twilio: Pay-as-you-go, no monthly minimum

Security

  • Invite-only: No open signup, invite code required
  • RLS: Circle membership isolation
  • JWT: 1h expiry, refresh rotation
  • Rate limits: 5 OTP/phone/hr, 3 fails → lockout
  • Webhook sig: Standard Webhooks verification
