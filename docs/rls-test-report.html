FAIL A4: Maya cannot see Sarah's private items (items_visible view)
Expected Empty result — private item hidden from Maya
HTTP 200
Result 1 item returned — private item (is_private=true) VISIBLE to Maya
Severity CRITICAL — Data leakage
Root cause: The items_visible view (migration 0016) runs as SECURITY DEFINER. The view owner is supabase_admin which has BYPASSRLS. When Maya queries items_visible, the underlying SELECT ... FROM items executes as supabase_admin, bypassing all RLS policies on the items table. Private items leak to all authenticated users.

Impact: Any circle member can read private items belonging to other members through the view, including brand, model, photos, and metadata (though price columns are still correctly NULLed by the CASE/WHEN in the view definition).

Fix: ALTER VIEW public.items_visible SET (security_invoker = true); — This makes the view execute with the privileges and RLS context of the querying user rather than the view owner.

Note: Direct table access (GET /rest/v1/items) correctly blocks private items (see A4b). The bug is isolated to the view.
